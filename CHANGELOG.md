## [Unreleased]
### Added
- 2026-10-16 Attendance: lateness, meeting button and overtime. Before check-in (and when the check-in window has closed) the card says how late it already is ("You are 4h 29m late. Office time started at 10:15"); after check-in the record stores minutes late. Pressing the Zoom/meeting button is recorded (first press of the day, `POST /workforce/attendance/meeting-join`, audited). A check-out after the new policy time `attendance.workdayEnd` (default 19:00, HR policy page) stores `overtimeMinutes`. HR and managers get a day sheet (`GET /workforce/attendance/day`, scoped): who came when, minutes late, who pressed the meeting button and when, check-out and overtime; month view and the attendance report gain late/meeting/overtime. Migration `20261016120000_attendance_late_meeting_overtime` (nullable columns, expand-only); HR corrections recompute lateness and overtime.
- 2026-10-16 Developer Panel "Feature access" (`/admin/developer/features`): switch screens and individual features on or off per role or per person. New table `feature_overrides` (migration `20261016100000_feature_access`) layered over the code permission catalogue: DENY removes a grant, GRANT adds one at a chosen scope, no row = default. Effective permissions (session, background principals, Access map user view) now include overrides; `devpanel:*` keys and the Developer role can never be overridden, you cannot change your own access, sensitive grants need explicit confirmation, every change is audited with before/after. API `/api/v1/dev-panel/features*`, permissions `devpanel:features:view|manage`.
- 2026-10-16 Site audit (goals, attendance, sales plan, role guide): campaign/sales plans could only be created, never edited or closed, and the form could not link a program/campaign/source so "leads so far" was always blank. Added `PATCH /api/v1/collaboration/plan-links/:id` (`xf-tasks:update`, audited, Planned→Active→Completed/Cancelled, closed plans final) and an edit dialog with program/campaign/source pickers. The 45-day goal now shows on every desktop dashboard next to today's attendance (it existed only on the mobile home). New Developer Panel tab "Role guide": per role, the pages rolled out (scope from the permission catalogue) and how each works, plus attendance, goals and sales-plan workflows. Also fixed a lint error in the mobile home header (setState in effect).
- 2026-10-16 Developer Panel v2 (5 parallel agents): Overview dashboard (live health, 24h alerts, integrations and backup status via optional `BACKUP_DIR`), Diagnostics (DB/Redis latency, failed outbox jobs with retry/retry-all/discard, bounded in-memory error and slow-request buffer, migrations status, build info via optional `GIT_COMMIT`/`BUILD_TIME`), Security (live sessions and kill, login history, locked accounts and unlock, one-time password-reset link, `devpanel.*` audit trail), Access map (role x permission matrix, effective permissions per user, flags as configured/not configured only, copy-only deploy/restart runbook), Maintenance mode (Redis flag, global interceptor returns 503 MAINTENANCE for everyone without `devpanel:access`, fail-open, public `GET /maintenance/status`, animated full-screen page and developer banner). New permissions `devpanel:diagnostics:view`, `jobs:manage`, `security:view`, `security:manage`, `config:view`, `maintenance:manage`. Developers land on `/admin/developer`. No migrations; discard sets the outbox row to DISPATCHED with a DISCARDED note (a real status needs a migration). Tests: apps/api/test/devpanel/*.spec.ts.

API `/api/v1/dev-panel` (overview, user list, set roles incl. DEVELOPER, revoke one user's sessions, force-logout everyone with a reason, read-only server/DB/Redis/worker/outbox/host snapshot); all writes audited (`devpanel.*`).
